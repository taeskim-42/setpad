# 기록 화면 — 40세트 한 화면

iPhone 17e 시뮬레이터(390×844 논리 픽셀, iOS 26.5), 디버그 빌드.
데이터: 운동 8종목 × 5세트, 세트마다 값이 다르고 사용자 운동명·lb·맨몸·시간 기록이 섞여 있다.

- `40-sets-390x844.png` — 키보드를 닫은 상태. 40세트가 전부 보인다. 한 열보다 넓은 값(`102.5×10`)은 두 열을 차지해 줄이 하나 늘어난다.
  식단 두 끼가 머리말에 있어 날짜·식단 줄은 위로 스크롤돼 있다 — 운동 기록은 전부 화면 안이다.
- `cell-editing-390x844.png` — 3세트 칸을 누른 상태. 그 세트만 넓은 입력 줄을 얻고, 키패드의 "세트 추가" 와 "완료" 가 다른 일을 한다.

같은 조건의 자동 검증은 `test/record_ux_test.dart` 의 "8. 오늘 한 세트 전부" 다.

## 무거운 실데이터 (긴 이름·102.5kg·메모·식단·같은 날 다른 문서)

같은 기기. 8종목×5세트에 긴 사용자 운동명, `102.5×11` 같은 넓은 값, 세트 메모 2개, 식단 2끼(열량 미상 1건), 같은 날의 다른 문서 1개를 넣었다.

- `heavy-fit-all-390x844.png` — **전체 보기: 충족.** 축소 없이(배율 1.000, 칸 글자 15pt) 두 문서의 운동·세트·메모가 한 화면에 들어온다. 넓은 값 다섯 칸이 제 폭으로 한 줄에 들어가면 그렇게 놓는다.
- `heavy-doc-top-390x844.png`, `heavy-doc-bottom-390x844.png` — **기본 문서 화면: 한 화면에는 미충족.** 머리말(날짜·섭취 합계·끼니 2줄·버튼)과 메모, 아래의 같은 날 기록까지 합쳐 약 1.2화면이라 스크롤이 필요하다. 세트는 하나도 접히거나 잘리지 않는다.
