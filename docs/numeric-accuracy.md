# 숫자 정확성 계약 — 2026-09-13

모델이 해석한 숫자·기간·조건은 제안이다. 사용자에게 확정된 계산 결과로 보여주거나 운동 설정에 저장하기 전에 확인을 받는다. 직접 운동과 지표를 선택하는 경로는 저장된 완료 기록을 코드로 계산한다.

## 적용 경계

- 모델에서 디코딩한 조회 계획은 모두 `requiresConfirmation`을 가진다. `doubts`가 비어 있어도 예외가 없다. `executeRecordPlan`도 미확인 계획의 실행을 막는다.
- 확인 화면에는 운동, 지표, 연도를 포함한 시작·종료 날짜, 무게 단위, 무게·횟수의 모든 상한·하한을 표시한다. 비교는 두 기간과 뺄셈 순서를, 순위는 개수와 내림차순을 표시한다.
- 검색어를 바꾸면 확인이 해제된다. 캐시에는 해석만 보관한다. 같은 질문으로 돌아와도 다시 확인한다. 언어·표시 단위·날짜가 달라지면 이전 확인이 적용되지 않는다.
- 자연어 운동 설정은 원문과 편집 가능한 이름·무게·단위·총 목표 횟수·세트당 횟수·목표 세트 수를 먼저 보여준다. 확인 전에는 운동 블록이나 완료 세트를 만들지 않는다. 취소하면 원문이 남는다.
- 확인 중 숫자를 수정했다면 이전 숫자가 포함된 원문을 운동 제목으로 재사용하지 않는다.
- 메모·종합 질문은 확인한 범위의 원본 기록을 보여준다. 앱의 검색 경로에서는 자유 서술 모델 답변을 생성하거나 표시하지 않는다. 근거 ID가 존재한다는 사실만으로 서술 속 숫자가 맞다고 볼 수 없기 때문이다.
- 현재 운동 설정은 일정·날짜·시간 목표를 표현하는 필드를 제공하지 않는다. 명확하게 감지한 일정·시간 문장은 일부 숫자만 적용하지 않고 입력 실패로 보존한다. 일정 관리 기능을 새로 추가한 것은 아니다.

## 확인한 계산 결함과 수정

- 사용자가 명시한 단일 기간은 모델이 다른 단일 기간을 반환했어도 우선 적용한다.
- 횟수 조건만 있는 문장에 모델이 붙인 무게 조건을 제거한다. 지원하지 않는 표현과 복합 의미까지 자동으로 확정하지는 않는다.
- 날짜 이동은 24시간 단위 빼기가 아닌 달력 날짜 연산으로 처리한다. 연말·윤년·서머타임 경계를 테스트한다.
- kg/lb 필터는 저장된 십진수 표현과 정확한 변환 비율 `1lb = 0.45359237kg`을 정수 분수로 비교한다. 경계값에 임의의 오차 허용치를 적용하지 않는다.
- 같은 단위의 원래 측정값은 저장 정밀도를 그대로 표시한다. 환산값·평균·차이·차트 축 등을 반올림할 때는 `≈`를 표시해 정확한 값과 구분한다.
- 문장형 운동 제목 대신 실제 운동 식별자 `block.exercise`로 집계한다.
- 합계·최고값·평균과 필터 판정에 필요한 측정값이 누락되면 일부 세트만으로 숫자를 만들지 않는다.

## 평가 계약
