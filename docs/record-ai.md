# 운동 기록 질문

목록 검색창의 문장은 기기 내 LLM이 의미를 해석하고, 코드가 명시된 기간·조건을 보정한다. 자연어 조회는 운동·지표·전체 기간·조건을 확인한 뒤 실행한다. 일반 운동명 검색과 지표 선택은 기존 검색과 코드 계산으로 처리한다. 현재 정책은 [숫자 정확성 계약](numeric-accuracy.md)을 따른다.

- 수치 질문은 검증된 조회 계획으로 변환한다. 무게·횟수·세트 수·운동 일수·기간 비교·순위는 저장된 완료 기록에서 코드로 계산한다.
- 메모, 계획, 종합적인 기록 질문은 확인한 범위의 원본 기록을 보여준다. 숫자나 날짜를 지어낼 수 있는 자유 서술 모델 답변은 앱의 검색 경로에서 표시하지 않는다.
- 운동 기록과 무관한 질문에는 “운동 기록과 관련된 질문을 해주세요.”를 표시한다. 기록 부족과 의미가 불분명한 경우는 따로 안내한다.
- 지난달·이번 달 등의 기간 경계와 kg/lb 변환은 코드로 처리한다. 모델 응답을 실행 코드나 SQL로 실행하지 않는다.
- 이름 목록과 근거의 길이를 제한하며, 생략된 근거가 있음을 모델에 명시한다. 집계는 요청 범위 전체를 대상으로 한다. 완료하지 않은 세트와 계획은 완료 실적으로 세지 않는다.
- 지원 기기에서 실제 로컬 모델을 사용한다. 모델이 준비되지 않은 기기는 상태별 안내와 일반 검색을 제공한다.

검증: Flutter analyze 0건, 테스트 207개 통과, iOS 시뮬레이터·Android debug APK·웹 빌드 성공. iOS 26.5 시뮬레이터의 실제 Foundation Models로 최대 무게, 순위, 무게 하한, 기간 비교, 메모 질문, 무관한 질문을 확인했다. 자동 테스트의 모델 응답은 테스트 대역이며 실제 언어 이해 검증과 구분한다.

실제 모델 검증 중 발생한 기간 경계 오류는 상대 기간을 코드에서 계산하는 방식으로, 세트와 반복 횟수 혼동은 근거 필드를 명시하는 방식으로 보완했다. 자유 서술과 의도 해석은 생성 모델이므로 모든 표현의 정확성을 보장하지 않는다. 근거 ID 검증은 출처의 존재를 검증하며 문장 전체의 사실성을 증명하지 않는다.

화면 검증 이미지: `artifacts/record-ai/light.png`, `dark.png`. 별도의 테스트 화면에서 작은 임시 기록으로 확인했다. 검증 도중 첫 임시 저장소가 실제 시뮬레이터 파일을 덮어쓰는 실수가 발생했고, 앱을 중지한 뒤 보관된 기존 운동 1개 및 설정 백업을 복구했다. 다른 작업의 151일치 파일은 `artifacts/record-ai/recovery/other-task-151-notes.json`에 별도 보관했다. 2026-09-09 사용자 요청에 따라 해당 151일치 파일을 시뮬레이터에 추가했다. 추가 전 기록과 설정을 백업하고 기존 2개 기록을 보존했으며, 앱 재실행 후 총 153개 기록과 가져온 151개 ID의 보존을 확인했다. 이후 검증 저장소는 임시 디렉터리로 격리했다.

# BPM과 타바타

운동 제목의 `120bpm` 또는 `bpm 120`은 박자 재생, `타바타` 또는 `tabata`는 20초 운동·10초 휴식·8라운드를 제공한다. `타바타 30/15 x6 100bpm`처럼 간격·라운드·박자를 함께 지정할 수 있다. 시작 버튼을 누르면 실행하며 앱이 비활성화되면 일시 정지한다. 한 번에 한 운동만 실행하고, 완료 기록은 임의로 생성하지 않는다.

Dart 타이머는 경과 시간으로 단계를 계산하고, 실제 박자는 iOS AVAudioPlayer·Android AudioTrack·웹 Web Audio의 반복 버퍼로 재생한다. 시간 경계·일시 정지·복귀·제목 해석은 테스트로 확인했고 iOS 실제 네이티브 오디오의 시작과 정지 호출도 성공했다. 실제 기기의 소리와 외부 음악 혼합은 기기에서 추가 확인할 수 있다.
