# 운동 기록 질문

목록 검색창의 문장은 Setpad 서버(gymdojo `/api/record-query`)를 거쳐 DeepSeek가 **질의 JSON 하나**(contract 2)로 바꾼다. 앱이 그 질의를 검증·보정하고 확인을 받은 뒤, 저장된 완료 기록에서 코드로 센다. 모델은 숫자를 답하지 않는다. 현재 정책은 [숫자 정확성 계약](numeric-accuracy.md)을 따른다.

- **질의**: 운동(최대 8)·제외, 기간, 마지막 N번, 무게·횟수 조건, 요일, 메모 낱말, 측정 1–3개를 담는다. 측정은 최고·평균 무게·추정 1RM·볼륨·추이·최다 반복·거리·시간·세트 수·총 횟수·운동한 날·마지막·처음·쉰 날, 14가지다. 여기에 운동이나 기간을 나란히 보는 비교, 운동·날·주·월·요일 묶음, 상위·하위 N, 합계·평균이 붙는다. 무엇을 셀지 말하지 않은 질문("기록 비교")은 최고·운동한 날·마지막을 보인다.
- **검증**(`RecordQuery.decode`): 모르는 키, 목록에 없는 값, 말이 안 되는 조합은 모두 실패로 본다. 조건을 조용히 버리지 않는다. 서버는 크기와 모양만 보고, 뜻은 앱만 본다.
- **규칙 층**: 글에 또렷이 적힌 기간, 이상·이하 조건, 한 갈래 의도 낱말은 모델보다 앞선다. 한국어와 영어만 알고, 메모 낱말은 여덟 언어를 안다. "지난달보다"처럼 두 범위를 견주는 말이 있으면 모델의 비교 기간을 접지 않는다.
- **결과**: 칸마다 `stats.answer`를 불러 계산의 원천을 하나로 둔다. 화면 모양은 코드가 정한다. 칸 하나는 숫자 카드, 날·주·월 묶음은 차트, 그 밖은 표(TableCard)다.
- **바로 답하는 경로**: 이름이 둘 이상 잡히면 [비교·최고·운동한 날·볼륨] 칩을 띄운다. 칩은 모델을 부르지 않고, 확인 없이 바로 센다. 오프라인이거나 무료 한도(30일 30회)를 다 써도 동작한다. 해석을 기다리는 동안 목록은 언급한 운동과 기간으로 걸러 둔다.
- **거절**: 운동 기록과 무관한 질문(unrelated), 목록에 없는 운동(missing), 무엇을 셀지 모르는 질문(clarify)은 안내 문구로 답한다. 부위("가슴 운동"), OR 조건, 칼로리, 후속 질문은 이번 판에서 clarify다. 조언을 구하는 질문("벤치 정체기인데 어떻게 깨?")은 관련 기록 조회로만 답한다. 한도를 다 쓰면 한도 문구를 보인다.
- **보내는 것**: 고정 지시문, 질문 문장(별칭만 정식 이름으로 바꾼 것), 앱 언어, 무게 단위, 올해 연도, 기기에 저장된 운동 이름 최대 60개, 그리고 `contract: 2`. 무게·횟수·날짜·메모 같은 기록 값과 계산 결과는 보내지 않는다. 서버는 질문 문장을 남기지 않는다.
- **평가**: 채점기와 질문 모음(`tool/questions/v2.json`, dev, heldout), 운영 모델 평가 방법은 [숫자 정확성 계약](numeric-accuracy.md)의 평가 계약에 있다. contract 2 이후 실제 모델 정확도는 아직 재지 않았다.

# BPM과 타바타

운동 제목의 `120bpm` 또는 `bpm 120`은 박자 재생, `타바타` 또는 `tabata`는 20초 운동·10초 휴식·8라운드를 제공한다. `타바타 30/15 x6 100bpm`처럼 간격·라운드·박자를 함께 지정할 수 있다. 시작 버튼을 누르면 실행하며 앱이 비활성화되면 일시 정지한다. 한 번에 한 운동만 실행하고, 완료 기록은 임의로 생성하지 않는다.

Dart 타이머는 경과 시간으로 단계를 계산하고, 실제 박자는 iOS AVAudioPlayer·Android AudioTrack·웹 Web Audio의 반복 버퍼로 재생한다. 시간 경계·일시 정지·복귀·제목 해석은 테스트로 확인했고 iOS 실제 네이티브 오디오의 시작과 정지 호출도 성공했다. 실제 기기의 소리와 외부 음악 혼합은 기기에서 추가 확인할 수 있다.
