# 서버로 가는 길 — 한 길이 막혀도 이어 가기

2026-09-21 맘마로그에서, 같은 API 서버로 가는 두 주소 중 **Railway 가 준 주소만** 중국 본토에서
TCP 연결이 안 되는 일이 있었다(DNS 는 됐고, 서울·싱가포르에서는 정상). 우리 도메인으로 가는 길은
통했다. 서버가 아니라 **진입 경로 하나**가 막힌 것이다. 중국만의 일이 아니다 — 어느 통신사, 어느
지역에서도 한 진입 IP 는 끊길 수 있고, 그 원인을 우리가 확정하지 못할 수도 있다.

목표는 "절대 안 막히는 IP" 가 아니라, **한 길이 실패해도 기록을 잃지 않고 다른 길로 이어 가는 것**이다.

## setpad 의 지금 상태

| 항목 | 상태 |
|---|---|
| 앱이 부르는 주소 | `https://gym.darak.studio` 하나(우리 도메인). 코드에 인프라 사업자 주소 없음 — `lib/api_route.dart`, `RecordAi.defaultEndpoint` |
| 사업자 주소가 남은 곳 | 앱 링크 도메인 목록의 `web-production-9cfc2.up.railway.app` — 이미 붙여 둔 옛 스티커용이다. API 호출에는 안 쓴다 |
| 연결 단계 시간 제한 | 8초(`connectTimeout`). 막힌 길에 1분씩 매달리지 않는다 |
| 예비 길로 갈아타기 | 구현됨(`FailoverClient`), **꺼져 있음** — 검증된 예비 주소가 아직 없다 |
| 접속 실패 시 로그아웃 | 하지 않는다. 401 일 때만 로그아웃(`Account._stillValid`) |
| 미전송 기록 | 기기에 먼저 저장하고 밀린 것은 다시 보낸다: 운동(`local_id`), 끼니(끼니 id), 같이 하기(revision+base), 공동 루틴(localId·version) |

## 갈아타는 규칙

- **연결 자체가 안 될 때만** 예비 길로 한 번 더 보낸다(소켓·TLS 단계의 실패).
- 서버가 답했으면(401·403·4xx·5xx) 길은 통한 것이다. 갈아타지 않는다.
- 다시 보내는 것은 **같은 요청**이다 — 같은 id, 같은 본문. 첫 요청이 서버에 닿고 답만 잃었어도 서버가 한 줄로 합친다.
- 요청 하나에 길마다 한 번씩만. 예비 길이 통하면 10분 동안 그쪽을 먼저 쓰고, 그 뒤 기본 길을 다시 본다.
- 두 길이 다 막히면 "그물 없음" 이다: 기록은 기기에 남고, 로그아웃하지 않고, 다음 기회에 보낸다.
- 원격으로 주소 목록을 내려받거나 푸시로 주소를 바꾸는 장치는 만들지 않았다. 주소 두 개로 시작한다.

## 예비 길을 켜려면 (아직 안 한 일)

1. 기본 길과 **다른 사업자·다른 진입 IP** 의 중계 서버를 **별도 도메인**에 둔다. 같은 API 서버·DB 로 넘기기만 한다(서버·DB 복제는 하지 않는다).
2. 중계는 HTTPS 로만 받고, `Authorization` 머리말과 본문을 **기록하지 않는다**.
3. 서버의 주소별 한도(`clientIp`)가 중계 서버의 IP 하나로 뭉치지 않게, 중계가 넘겨주는 원래 주소를 신뢰하는 설정을 같이 맞춘다.
4. 대상 지역의 **실제 통신사 회선**에서 로그인·조회·저장·동기화를 확인한다. 한 번 통했다고 계속 통한다는 보장은 없다.
5. 확인된 주소로 빌드한다: `--dart-define=API_BACKUP=https://<예비 도메인>`.

## 완료 판정 (맘마로그 사례의 기준을 그대로)

| # | 기준 | setpad |
|---|---|---|
| 1 | 기본 길 차단 → 업데이트 없이 예비 길로 연결 | 앱 장치는 테스트로 확인(`test/api_route_test.dart`). **실제 예비 길이 없어 미충족** |
| 2 | 서버 저장 직후 응답 차단 → 재시도해도 한 건 | 확인(앱: 같은 id 재전송 / 서버: 끼니·세션·계획의 멱등 테스트) |
| 3 | 두 길 차단 → 종료·재실행 뒤에도 미전송 유지 | 확인(끼니 `dirty`, 같이 하기 revision, 공동 루틴 초안이 디스크에 남는다) |
| 4 | 연결 복구 → 순서와 최종 값 보존 | 확인(밀린 것은 최신본 한 번으로 맞고, 오래된 업로드는 거절된다) |
| 5 | 구버전에서 쌓인 기록 → 업데이트 후 동기화 | 저장 형식 호환은 테스트했다. **구버전 설치 → 오프라인 → 업데이트 → 재연결 실기 검증은 안 했다** |
| 6 | 경로 장애 → 감시가 탐지·알림 | **없음.** 대상 지역의 외부 측정 지점에서 기본·예비 길을 주기적으로 보고, 복수 지점·연속 실패로 알려야 한다 |

## 보장하지 않는 것

- 우리 도메인의 DNS 를 바꾸면 모든 기기에 몇 분 안에 반영된다는 것
- 전용 IP 면 막히지 않는다는 것
- 이미 설치된 구버전이 새 주소를 알게 된다는 것 — 앱에 든 주소는 업데이트로만 바뀐다
- 기기에 대기열이 있으니 구버전의 기록도 전부 안전하다는 것
